# v0.2.0-alpha.1（测试预发行）

在 v0.1.0-alpha.1 的 Runtime 上加了第一个产品：**在线多租户 Coding Agent 的 MVP**（当时在 Runtime 仓库的 `products/coding`，2026-10-26 迁到本仓库；这个预发行与它的标签留在 Runtime 仓库）。用于试跑与反馈，不要用在生产环境。下面的命令是当时在 Runtime 仓库里的用法；现在的用法见本仓库的 README。

## 新增

- **Coding Agent 网页**：开发登录（租户 + 用户名）；新建项目（https Git 地址、内置示例、空项目）；用一句话下任务；实时时间线（受理、轮次、阶段、节点、Reviewer 判定、结束）；需要确认的步骤弹出审批卡片；交付结果与用量；改动页（diff、提交、下载补丁、丢弃）；文件浏览；提交历史。
- **coding-web 服务（Go）**：经 Task API 下任务、代理 SSE（浏览器带不了 Authorization 头）、按租户隔离项目与任务、路径一律校验在工作区内、改写请求要带自定义头防跨站请求；新租户首次登录时把 effect 上限写成 write_reversible。
- **Docker 沙箱**：Worker 设 `AR_TOOL_SHELL_SANDBOX=docker` 时，`shell_run` 在一次性容器里跑：只挂载本项目的工作区、不联网、限 CPU、内存与进程数、去掉全部 capability。
- **一条命令起整套**：`scripts/dev_stack.py up --coding --sandbox docker`。

## 验证

- `products/coding` 的 Go 测试（登录、建项目、改动、提交、提交任务、租户隔离、CSRF 头、路径校验）；Worker 的配置与工具测试；全部契约测试（396 条）。
- 真模型从网页走通一遍：示例仓库的“修好 CI”任务被修好，Reviewer 核对 5 条测试通过后判 done；跑测试的两次 `shell_run` 都在 Docker 沙箱里；12 次模型调用，约 0.10 美元。

## 怎么试

```bash
uv sync --all-packages --locked
uv run --no-sync python scripts/dev_stack.py up --coding --sandbox docker
```

打开输出里的 `Coding` 地址。离线试用加 `--provider mock --decisions stub`。详见 `products/coding/README.md`。

## 已知问题与限制

- 开发登录，没有密码与 OAuth；只适合在可信网络里试用。
- 元数据存 JSON 文件、单实例；工作区要在 Worker 与 coding-web 共享、Docker 能挂载的本地盘上。
- 不推送到 GitHub、不开 PR；进度只到节点级，没有 token 级流式输出。
- 沙箱镜像默认 python:3.13-slim，别的语言要换 `AR_TOOL_SHELL_IMAGE`。
- 产品的验收测试按“先实现后补测”（经人确认）第二版补齐；v0.1.0-alpha.1 的已知问题仍然存在（夜间端到端偶发失败等）。
