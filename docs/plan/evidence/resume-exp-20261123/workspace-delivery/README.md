# Coding Agent 多副本工作区重试实验

## 结果与采用

两版各跑 28 组。在重复 POST、跨副本轮询、两者混合的 12 组中，原版全部发生同一操作的下游并发查询，候选全部只有一个查询者。四个 Web 进程观察同一操作时，同一时刻发往 Runtime 的状态查询峰值从 4 降到 1。全部场景验收由 16/28 升到 28/28。两版都得到 32 个应有项目，对应模拟 Runtime 接受的 32 个唯一创建操作。差异发生在执行者与重复查询层。[对照汇总](comparison.json) · [基线逐组](baseline.json) · [候选逐组](candidate.json)

3 轮 Go race 工作区回归通过。完整 server 包在系统 Chrome 上通过（234 个用例或子用例成功、1 个按环境跳过），Windows amd64 测试程序交叉编译成功。Windows 没有运行多进程场景。

本轮采用代码改动，未部署到线上。本机有真实独立进程、TCP、登录、JSON 操作日志、项目落盘、杀进程和跨进程文件锁。Runtime Workspace HTTP 接口由可控服务模拟，创建操作按请求 ID 去重。未调用模型或创建远程沙箱。本轮测试成本为零模型费用。

## 题单与验收口径

使用固定的七种请求安排，每种四次，共 28 个场景 ID。没有训练集或随机用户抽样。每组启动 1、2 或 4 个真正的 `coding-web` 可执行程序，使用同一个临时数据目录；每个 Web 进程经正常 HTTP 登录同一租户和用户。每组的 Runtime 等待同一个放行信号，测量同一操作在放行前是否有多个 Web 进程同时查询。每组结束后清理各进程及其专属目录。[冻结协议](cohort.json) · [可执行测量脚本](run.py)

| 请求安排 | 每组进程 | 核验 |
|---|---:|---|
| 正常单次新建 | 1 | 一个项目，最终 HTTP 201 |
| 同键重复 POST | 2 | 相同操作 ID；每次 POST 均返回 202 |
| 同一操作跨副本轮询 | 4 | 其余三个副本各返回 RUNNING |
| 同键 POST 和轮询混合 | 4 | 操作 ID 一致；一个后台查询者 |
| 两个不同键 | 2 | 两个操作在放行前都进入 Runtime，最终有两个项目 |
| 接受创建后杀掉活动 Web 进程 | 2 | 另一副本凭已认证轮询继续，最终仍是原项目与操作 ID |
| 同键不同创建参数 | 2 | 原结果保留，第二个请求 HTTP 409 |

主要指标按场景检查独立键的行为、并发度、用户可见结果和重试请求是否在 1 秒内返回。每组另记录 Runtime 的创建请求、唯一操作、最终项目数和 API 状态。测试中的 HTTP 等待窗口为 400 ms。重复观察者的 12 组请求批次实测最近秩 P95 为基线 1.17 ms、候选 46.09 ms；此处的 P95 就是 12 组中的最大值，仅作本地开销记录。该值不支持声称延迟改善。

## 改动与运行

基线涉及的四个源码文件与仓库提交 `0cd2c890d214a53a3768568b7d80103eb0fd7341` 相同。源码前后摘要、两次实际运行的二进制摘要、脚本摘要、协议摘要均可回查。候选在录入首个请求时，沿用 Store 的共享元数据锁原子确认该键的请求摘要。工作流使用每个操作各自的锁文件，执行者以非阻塞的跨进程排他锁获得执行权。旁观副本可以立即返回相同操作的状态。取得锁后重读操作日志，避免使用收到请求时已过时的状态。锁文件的 inode 独立于原子替换的 JSON 日志，进程退出时内核释放锁。[工作区实现](../../../../../internal/server/workspace_http.go) · [回归测试](../../../../../internal/server/workspace_http_test.go)

在 `coding-agent` 仓库所在的工作区，分别从以上基线和包含修复的源码编译同一个入口。实验只监听 127.0.0.1，使用临时签名材料并在每组结束后清理。每个二进制各运行一次脚本。两个输出路径应使用新文件名以保留原收据。

```sh
go build -o /tmp/coding-web-delivery ./cmd/coding-web
python3 docs/plan/evidence/resume-exp-20261123/workspace-delivery/run.py \
  /tmp/coding-web-delivery /tmp/coding-web-delivery-result.json
go test -race ./internal/server -run '^TestWorkspaceHTTP' -count=3
```

跨进程验收发生在 macOS 本机卷。生产多机部署应对实际共享卷另做锁语义验证；各副本使用独立磁盘时，这种锁无法协调。进程活着但下游响应过慢时，仍由现有工作区操作超时和恢复流程控制。更多面试追问见[实验复盘](../../../../../../8-legged/实验复盘/CodingAgent多副本工作区幂等-20261123.md)。
